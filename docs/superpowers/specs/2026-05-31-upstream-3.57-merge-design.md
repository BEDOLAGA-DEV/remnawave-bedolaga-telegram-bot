# Upstream merge v3.54 → v3.57 (bot) — design

**Date:** 2026-05-31
**Scope:** мерж upstream BEDOLAGA-DEV/remnawave-bedolaga-telegram-bot (main, до v3.57.0) в наш форк master, сохраняя все локальные кастомизации + 10 фич
**Status:** Draft

## Проблема

Форк отстал на 126 коммитов от upstream/main (последний смерженный — v3.54.0,
текущий upstream — v3.57.0; теги v3.55/v3.56/v3.57). Нужны upstream-нововведения
БЕЗ потери наших 255 кастомных коммитов (10 фич: churn-save, traffic-upsell,
birthday, freeze, trial-invite, speedtest, traffic-cap, OAuth-fix, partner-
showcase, milestones + форк-кастомизации).

Прямой `git merge upstream/main` даёт:
- **25 конфликтов кода** (models.py, subscription_service, config, inline.py,
  webapi/users, my_subscriptions, purchase, start, admin/users, remnawave_service,
  payment/common, и др. + pyproject/uv.lock/3 теста).
- **Коллизию миграций**: upstream добавил 0076-0087 (12 новых) с revision-id
  `0076`-`0087`; у нас эти НОМЕРА заняты (3.54-renumber + наши 0096-0100).
  Дубли revision-id → multiple alembic heads → `DuplicateColumnError` на проде.
  Именно это ломало прод после 3.54.

## Решение

Ветка `upstream-3.57-merge` от master (backup `backup-before-upstream-3.57`
уже создан). 3 фазы: миграции → код → верификация. Union-резолв сохраняет
обе стороны. После прохождения тестов → master.

### Фаза 1: миграции — renumber upstream → 0101+

Upstream-миграции линейны: `0075←0076←…←0087` (revision=down chain).
Все 12 файлов 0076-0087 — НОВЫЕ по имени (не пересекаются с нашими
именами), но их revision-id 0076-0087 коллидят с нашими.

**Renumber-map** (upstream → наш):
```
0076 → 0101  (down_revision: '0075' → '0100')   # наш head 0100
0077 → 0102  (down: '0076' → '0101')
0078 → 0103  (down: '0077' → '0102')
0079 → 0104  ... 0080→0105, 0081→0106, 0082→0107,
0083 → 0108, 0084→0109, 0085→0110, 0086→0111,
0087 → 0112  (down: '0086' → '0111')
```

Процедура:
1. Мерж `git merge upstream/main --no-commit` (получаем все 12 upstream-файлов
   в дереве + 25 конфликтов).
2. Скрипт `_renumber_migrations_357.py` (воссоздать — старый удалён после 3.54):
   - для каждого файла 0076-0087: переименовать `0076_*.py`→`0101_*.py` и т.д.;
   - внутри файла: `revision='0076'`→`'0101'`, `down_revision='0075'`→`'0100'`
     (первый), далее `down='00NN'`→`'01MM'` по карте.
   - наш head 0100 остаётся; новая цепочка 0101→…→0112 цепляется за 0100.
3. Наши 0096-0100 не трогаем (они конфликта по имени не дают — упомянуты
   как контекст).

Проверка после: `alembic heads` → ровно ОДИН head (0112).

### Фаза 2: код — 25 конфликтов, union-резолв

25 конфликтных файлов. Стратегия по типам:

**Модели/сервисы (бизнес-логика):**
`app/database/models.py`, `app/services/subscription_service.py`,
`app/services/remnawave_service.py`, `app/services/payment/common.py`,
`app/database/crud/subscription.py`, `app/utils/subscription_utils.py` —
**ручной union**: сохранить наши добавления (поля фич, методы) + взять
upstream-новое. Урок 3.54: следить за дублями enum/колонок в models.py
(тогда был AURAPAY-дубль + слитые классы). Каждый resolved-файл — проверить
на дубли def/class/Column.

**Хендлеры/клавиатуры:**
`app/handlers/start.py`, `app/handlers/admin/users.py`,
`app/handlers/subscription/{my_subscriptions,purchase}.py`,
`app/keyboards/inline.py` — union; наши callbacks (`nz!_*`, фичи-кнопки)
+ upstream-хендлеры сосуществуют.

**Cabinet/webapi:**
`app/cabinet/routes/{__init__,admin_users,auth}.py`,
`app/cabinet/auth/telegram_auth.py`, `app/webapi/routes/users.py`,
`app/external/webhook_server.py` — наши роуты (showcase, milestones,
freeze, speedtest, traffic-cap) НЕ должны выпасть; union + проверить
include_router.

**Конфиг/инфра:**
`app/config.py` — union (наши 10 env-флагов + upstream-настройки).
`pyproject.toml` — union deps. `uv.lock` — НЕ резолвить вручную:
взять одну сторону + `uv lock` регенерация.
`app/logging_handler.py`, `app/services/admin_notification_service.py` — union.

**Тесты:**
`tests/conftest.py`, `tests/middlewares/test_channel_checker_payload.py`,
`tests/services/test_account_merge_service.py` — union; наши фикстуры +
upstream.

### Фаза 3: верификация

1. `alembic heads` → один head (0112).
2. `alembic upgrade head` на временной SQLite/тест-БД (dry, не прод) —
   проходит без DuplicateColumn.
3. `import app.main` / `import app.bot` — без ImportError.
4. `pytest tests/services/ -q` — нет НОВЫХ падений vs baseline (~29
   пре-existing fail зафиксировать ДО мержа для сравнения).
5. Наши 10 фич на месте: grep ключевых символов (PartnerPromo,
   ReferralMilestone, FreezeService, SpeedtestService, и т.д.) + их
   миграции 0096-0100 целы.
6. `git diff master HEAD --stat` — sanity объёма.

## Что НЕ входит

- Cabinet upstream-мерж (отдельная задача #13, после бота).
- Рефактор upstream-кода (берём как есть).
- Включение новых upstream-фич по дефолту (наследуем их дефолты).
- Прод-деплой/`alembic upgrade` на проде (отдельно, после мержа).

## Архитектура

```
master (clean, backup-before-upstream-3.57 saved)
  └── branch upstream-3.57-merge
        ├── Фаза 1: git merge upstream/main --no-commit
        │     └── _renumber_migrations_357.py: 0076-0087 → 0101-0112, chain onto 0100
        ├── Фаза 2: union-resolve 25 conflicts (models/services/handlers/cabinet/config/tests)
        │     └── uv.lock: regen via `uv lock`
        ├── Фаза 3: verify (alembic single head + dry upgrade + imports + pytest + features intact)
        └── commit → review → merge to master
```

## Поток данных (исполнение)

1. Зафиксировать baseline pytest-fail count на master ДО мержа.
2. branch upstream-3.57-merge; `git merge upstream/main --no-commit`.
3. Renumber миграций (Фаза 1), проверить alembic heads=1.
4. Union-резолв кода по файлам (Фаза 2), помечать resolved (`git add`).
5. Regen uv.lock.
6. Верификация (Фаза 3).
7. Commit; финальное ревью diff; merge master.

## Обработка ошибок

- Мерж идёт грязным до полного резолва — backup-ветка = откат (`git merge
  --abort` или `git reset --hard backup-before-upstream-3.57`).
- alembic multiple heads после renumber → перепроверить down_revision-цепь.
- models.py дубль-колонка/enum (урок 3.54) → ручная вычитка resolved-файла.
- uv.lock конфликт → не мержить руками, `uv lock` пересоздаёт.
- Тест-регресс (новое падение не из baseline) → разобрать конкретный файл.
- Наша фича пропала в union → восстановить из master-стороны конфликта.

## Тестирование

- alembic: single head, dry upgrade проходит.
- pytest services-suite: дельта 0 новых падений vs baseline.
- import smoke: app.bot, app.main, app.cabinet.routes.
- feature-presence grep: 10 фич + миграции 0096-0100.

## Rollback

- `backup-before-upstream-3.57` = master до мержа.
- Вся работа на `upstream-3.57-merge`; master не трогаем до зелёных тестов.
- `git merge --abort` (в процессе) / `git checkout master` + удалить ветку
  (если передумали).
