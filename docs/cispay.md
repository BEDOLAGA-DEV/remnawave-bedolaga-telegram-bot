# CisPay

Интеграция использует размещённую у CisPay платёжную страницу. Контракт проверен
по [документации](https://cispay.app/developers) и
[официальной OpenAPI](https://cispay.app/api/merchant/v1/openapi.json).

## Настройка

Включите `CISPAY_ENABLED`, задайте `CISPAY_SHOP_ID`, `CISPAY_API_KEY` и нужные
методы: `CISPAY_CARD_ENABLED`, `CISPAY_SBP_ENABLED`. Криптовалюта включается
отдельно: `CISPAY_CRYPTO_ENABLED=false` по умолчанию. Базовый адрес API —
`https://api.cispay.app`. Ключ не передаётся в браузер.

В кабинете провайдера укажите публичный HTTPS URL приложения с путём
`CISPAY_WEBHOOK_PATH` (по умолчанию `/cispay-webhook`). Подпись `X-Signature`
проверяется как HMAC-SHA256 исходного тела запроса с API-ключом.

Настройки могут переопределяться из БД. Ограничения способов оплаты, групп
пользователей и сумм действуют и при прямом запросе создания платежа. Для карты
минимум составляет 5000 копеек; больший локальный минимум сохраняется. Для
криптовалюты дополнительно действует минимум магазина на стороне CisPay.
Перед созданием проверяются активность магазина и доступность метода.
Общий способ выбирает разрешённый CARD/SBP; криптовалюта требует явного выбора.

## Суммы и подтверждение

Заказы приложения создаются в RUB; иная `CISPAY_CURRENCY` отключает интеграцию.
Для CRYPTO ответ может содержать `amount` в USD-центах. Зачисляется только
исходная рублёвая сумма заказа после проверки `source_amount` и
`source_currency=RUB`. Если денежному webhook не хватает этих полей,
выполняется авторизованный запрос статуса. Текущий обменный курс для
восстановления исходной суммы не используется.

Локальная запись заказа и данные гостевой покупки сохраняются до запроса
создания счёта, чтобы принять ранний webhook. Изменение баланса, транзакция и
оплаченный статус записываются атомарно. Повторные и конкурентные уведомления
не должны повторно начислять деньги. Выдача гостевой покупки выполняется после
фиксации оплаты; восстановление использует сохранённую запись.

`is_sandbox` и `block_reason` исключают реальное зачисление и выдачу покупки.
Тестовые платежи помечаются в интерфейсах и исключаются из финансовой статистики.
Идентификатор Telegram-покупателя сохраняется совместимым с прежней интеграцией,
чтобы не обходить ограничения покупателя у провайдера.

События `subscription.activated/cancelled/failed` проверяются, но не считаются
оплатой. Рекуррентные списания, возвраты через API, выплаты и ввод реквизитов
карты внутри приложения этой интеграцией не реализуются. Входящий REFUNDED
не списывает автоматически ранее зачисленный баланс: возврат требует сверки
оператором. REFUNDED до подтверждения оплаты блокирует последующее начисление.

## Сеть и обновление

Срок жизни ссылки определяет провайдер; обещания фиксированных 30 минут нет.
Статус учитывает `expires_in_seconds`. Повторное создание POST после сетевой
неопределённости автоматически не выполняется: у провайдера уникальный order_id
не является гарантией идемпотентного POST. Сохранённый заказ можно проверить
по order_id. Опрос имеет общую для процессов паузу и учитывает Retry-After.

Миграция `0136` добавляет `is_sandbox` и `next_check_at`. Исторические зачисления
не пересчитываются. Откат миграции запрещён при наличии sandbox-записей, чтобы
не потерять их происхождение. Не меняйте магазин с незавершёнными платежами:
новые записи привязаны к исходному shop ID, а для старых записей без него
используется текущая настройка магазина.

Поддерживаемые пользовательские поверхности — Telegram-бот и API кабинета.
В отдельном старом MiniApp API поддержки CisPay нет.

## Локальная проверка

Контракт HTTP и webhook покрывают `tests/services/test_cispay_http_contract.py`
и `tests/webserver/test_cispay_current_webhook.py`. PostgreSQL-сценарии находятся
в `tests/database/test_cispay_payments_postgres.py` и
`tests/database/test_cispay_lifecycle_postgres.py`: повторные уведомления,
конкуренция, rollback, sandbox, криптоконвертация, ранние callbacks и гостевая
выдача. Используйте отдельную БД через `TEST_DATABASE_URL` и
`REQUIRE_POSTGRES_TESTS=1`; Python-команды запускайте через `uv run --frozen`.

Локальный HTTP-стенд не заменяет контрольную оплату у реального провайдера.
