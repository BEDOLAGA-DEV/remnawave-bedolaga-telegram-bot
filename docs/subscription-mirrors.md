# Запасные адреса подписки

Опциональная настройка `SUBSCRIPTION_MIRROR_LINKS` позволяет открыть ту же
подписку через другой домен. Она не создаёт вторую подписку или аккаунт панели,
не меняет срок, лимит устройств или трафик. Исходная `subscription_url` сохраняется.

```dotenv
SUBSCRIPTION_MIRROR_LINKS=Запасная 1|https://mirror.example;Запасная 2|https://reserve.example
```

Настройка доступна в разделе «Кнопка подключения» в настройках бота. Действуют
обычные правила настроек проекта: значение из окружения может иметь приоритет
над сохранённым в БД; интерфейс показывает блокировку редактирования из окружения.

## Требования к адресам

- Только домены оператора с HTTPS, отдающие **те же пути подписок**. Сначала
  настройте домен, сертификат и маршрутизацию на своей стороне. Настройка бота
  не создаёт зеркало автоматически.
- Формат записи: `Название|https://домен`. Разделитель записей — `;` или новая
  строка. До 100 уникальных адресов; название — до 64 символов.
- Не указывайте путь, query-параметры, фрагмент, логин или пароль. Путь и параметры
  берутся из текущей ссылки конкретной подписки, включая после её перевыпуска.
- Одинаковые адреса объединяются, основной адрес повторно не предлагается.
- Чужой домен получит секретную ссылку подписки. Используйте только доверенные
  домены, которыми управляете. Бот не проверяет их сетевую доступность и не
  переключает пользователя автоматически: блокировка зависит от сети клиента.

Неправильный ввод в интерфейсе отклоняется до сохранения. Неправильные записи
в старой конфигурации или `.env` пропускаются, чтобы не сломать всё меню.
Пустое значение отключает выбор без изменения подписок и панели.

## Пользовательские экраны

В кабинете используется компактный выбор рядом со ссылкой и действиями
подключения. Выбор относится к конкретной подписке пользователя и применяется
к копированию, QR и импорту. В браузере сохраняется только идентификатор адреса,
не сама секретная ссылка. Другой пользователь или другая подписка не наследуют
этот выбор. Если адрес убран из конфигурации, используется основная ссылка.

В Telegram выбор находится рядом с подключением. В длинном списке есть страницы.
Выбранный адрес используется в текущем сообщении подключения. Возврат к старому
сообщению не переписывает его кнопки; Telegram и кабинет не синхронизируют выбор
между собой. Ссылки строятся заново при обработке выбора, с проверкой владельца
подписки.

Поддерживаются `guide`, `link`, `miniapp_subscription`. При скрытии ссылки,
`happ_cryptolink` или `miniapp_custom` выбор не добавляется: исходная ссылка не
раскрывается и собственный маршрут подключения не подменяется. Гостевой экран
покупки без авторизации остаётся со своей ссылкой: API подписок аккаунта для
него недоступен.

## API

`GET /cabinet/subscription/connection-link?subscription_id=...` возвращает
существующие поля и дополнительно `subscription_id`, `mirrors`:

```json
{
  "subscription_id": 42,
  "mirrors": [{
    "id": "opaque-origin-id",
    "label": "Запасная 1",
    "url": "https://mirror.example/demo"
  }]
}
```

`mirrors` содержит только альтернативы. При выключенной настройке или
неподдерживаемом режиме это пустой список. Идентификатор стабилен при
переименовании и перестановке адресов; изменение домена меняет идентификатор.
Доступ к чужой подписке запрещён существующим серверным разрешением подписки.
