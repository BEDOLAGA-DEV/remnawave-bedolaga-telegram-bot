# Доступные способы оплаты через Web API

`GET /payment-methods` возвращает только названия способов пополнения баланса.
Авторизация стандартная для административного Web API: `X-API-Key`. JWT-сессия
личного кабинета не требуется.

Список читается при каждом запросе из того же сервиса, что использует кабинет:
учитываются настройка провайдера, флаг включения в админке, порядок отображения,
переопределённые названия и включённые подспособы оплаты.

```http
GET /payment-methods
X-API-Key: <API_KEY>
```

Пример ответа:

```json
[
  "СБП (QR) (Platega)",
  "Карты (RUB) (Platega)",
  "Криптовалюта (Platega)",
  "СБП (CisPay)"
]
```

Способы с подвариантами раскрываются как `название варианта (название провайдера)`.
Для остальных возвращается отображаемое название способа. Ответ не содержит
ID, описания, лимитов, реквизитов, ключей провайдеров или платёжных ссылок.
Если способов нет, возвращается `[]`.

Без `user_id` ответ содержит общий каталог включённых способов. Пользовательские
фильтры в этом режиме не применяются, поэтому такой ответ не подтверждает
доступность всех перечисленных способов конкретному человеку.

Для списка конкретного пользователя передайте его **внутренний** Bedolaga ID:

```http
GET /payment-methods?user_id=42
X-API-Key: <API_KEY>
```

Применяются те же фильтры, что в кабинете: тип аккаунта, первое завершённое
пополнение и промогруппы. Telegram ID нельзя подставлять вместо `user_id`.

Ошибки: `401` при отсутствии или неверном API-ключе, `404` для отсутствующего
пользователя и `422` для некорректного `user_id`.
