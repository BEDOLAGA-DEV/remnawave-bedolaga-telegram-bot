# Меню команд Telegram

Обработчики и выпадающий список команд Telegram — разные механизмы. Список обслуживает
`app/services/bot_commands.py`, фоновую задачу запускает и останавливает `main.py`.

- Общий список `/start`, `/contests` публикуется только в `AllPrivateChats`.
  `/paysupport` добавляется только при действующем `TELEGRAM_STARS_ENABLED=true`,
  как и в Telegram-флоу приёма Stars; при выключении удаляется следующей сверкой.
- Для положительных Telegram ID из действующей настройки `ADMIN_IDS` публикуется полный
  список в `Chat`: пользовательские команды и `/admin_help`, `/rules_stats`, `/clear_rules`,
  `/monitoring`. Это тот же критерий, который используют Telegram-обработчики
  `admin_required`. Роли кабинета и администраторы Telegram-групп сами по себе не дают этих прав.
- Описания берутся через общий `get_texts` из ключей `BOT_COMMAND_START`,
  `BOT_COMMAND_CONTESTS`, `BOT_COMMAND_ADMIN_HELP`, `BOT_COMMAND_RULES_STATS`,
  `BOT_COMMAND_CLEAR_RULES`, `BOT_COMMAND_MONITORING`. Работают встроенные переводы
  и дополнительные JSON/YAML из `LOCALES_PATH`, включая переопределения оператора.
  Перечень языков не зашит в сервис: публикуются `AVAILABLE_LANGUAGES` и вариант
  без language_code на `DEFAULT_LANGUAGE`. Для отсутствующих ключей действует
  общий fallback локализации; некорректное описание заменяется английским.
  `ua` публикуется как `uk`; региональный код Telegram сокращается до двухбуквенного
  языка, но перевод загружается по полному имени локали. При нескольких вариантах
  одного языка в AVAILABLE_LANGUAGES последний задаёт описание общей области этого языка.
  Языковые варианты выбирает Telegram по языку клиента, а не профиля кабинета.
  Изменения файлов используют общий механизм сброса кеша переводов.
- Сверка запускается сразу, затем каждые 60 секунд. Изменение применённых runtime-настроек
  не требует перезапуска. Само редактирование файла `.env` не обновляет работающий процесс.
- Удалённые администраторы и локали очищаются через `deleteMyCommands`. Персональное меню
  после удаления уступает общему. Меню не является механизмом авторизации: ручной ввод
  административной команды всегда проходит прежнюю проверку прав.
- Журнал созданных областей хранится в `system_settings` под внутренним ключом
  `bot_command_scopes:<bot_id>`. Перед внешней записью сохраняется намерение: при потере
  ответа или перезапуске область не теряется. Это не редактируемая настройка оператора.
- Внутри процесса неизменные списки повторно не отправляются. После перезапуска выполняется
  сверка публикацией. Между успешными запросами пауза 100 мс; при `retry_after` пакет
  немедленно прерывается и соблюдается указанная задержка. Ошибка одного недоступного
  административного чата не блокирует остальные. Ошибки повторяются без остановки бота.
- Остановка завершает задачу, но не удаляет пользовательское меню. Неизвестные этому
  сервису области, созданные вручную в BotFather или другим инструментом, не удаляются:
  Bot API не предоставляет перечень всех существующих пар scope/language_code.

## Платёжная поддержка

`/paysupport` регистрируется перед обработчиками состояний и не сбрасывает текущую
покупку. Доступны обращение с предзаполненной темой оплаты, существующие тикеты
и настроенный контакт поддержки. Скрытое SUPPORT_MENU_ENABLED не скрывает этот вход.
При contact-режиме предлагается контакт; если режим изменился во время ввода обращения,
создание отменяется и показывается актуальный способ связи.

Команда остаётся доступной по ручному вводу после отключения новых Stars-платежей:
обращения по прежним платежам должны сохранять путь в поддержку. Для неизвестных,
удалённых и заблокированных аккаунтов выводится контакт без создания/восстановления
аккаунта и без изменений баланса или подписки. Оператору нужен действующий SUPPORT_USERNAME
для такого пути; отключение контактного пункта обычного меню не скрывает его здесь.

Серверный флаг public_payment_support допускает только read-only ответ этой команды
в private chat через ограничения канала, имени, техработ, blacklist и состояния аккаунта.
Никакие флаги из входящего текста не принимаются. Общий троттлинг сохраняется.
Обычные операции тикетов и возврат в поддержку помечены support_access: они проходят
через канал/имя/техработы, но сохраняют auth, blacklist, запреты обращений и проверки
принадлежности тикета. Административные обработчики не получают этот обход.

Тикет используется тот же, что в кабинете: отдельной базы обращений или новой категории
не добавлено, тема оплаты записывается в заголовок. `/support` и `/terms` в эту задачу
не добавлялись. Обработка Stars `refunded_payment` — отдельный денежный сценарий,
не реализованный этим исправлением.

Контракт: https://core.telegram.org/bots/api#setmycommands,
https://core.telegram.org/bots/api#deletemycommands,
https://core.telegram.org/bots/api#botcommandscope.

Проверки используют имитацию Bot API и отдельную тестовую БД; живое меню Telegram локально
не меняется. API и интерфейс кабинета этим изменением не затрагиваются.
