# AI Support Bot

Отдельный Telegram-бот ИИ-поддержки на базе RAG и GPT API. Работает самостоятельно (со своим токеном), поднимается вместе с основным проектом через общий `docker-compose`, но не зависит от кода основного бота.

## Возможности

Карта веб-кабинета, источники названий и ограничения навигации: [WEB_NAVIGATION.md](WEB_NAVIGATION.md).

Сбор данных о платеже и обновление аккаунта по ходу разговора: [DYNAMIC_CONTEXT.md](DYNAMIC_CONTEXT.md).

- Честно представляется ИИ-ассистентом (никакой имитации живого оператора) и передаёт вопрос человеку, когда не знает точного ответа
- Отвечает пользователям в Telegram на основе базы знаний (прошлые переписки поддержки) через RAG
- Принимает и анализирует фото/скриншоты (GPT Vision)
- Подтягивает данные пользователя из БД основного проекта (баланс, подписки, платежи) и из Remnawave API
- Веб-админка с разделом ИИ-поддержки:
  - системный промпт, модель ИИ, температура, Top-K и другие параметры (меняются на лету, без перезапуска)
  - загрузка JSON-экспорта переписки как базы знаний (автоматическая разбивка на чанки, эмбеддинги, дедупликация — старые дубли не создаются повторно)
  - управление базами знаний (вкл/выкл/удаление)
  - история диалогов с ИИ-агентом (хранятся последние N сообщений, по умолчанию 100, чтобы не забивать память)
- Понимает намерение пользователя (техпроблема / оплата / инструкция / просто общение) и по-человечески отвечает на болталку («привет», «как дела», «спасибо»)
- Знает максимум о пользователе: подписки с остатком дней и трафиком, баланс, промогруппа, рефералы, ограничения аккаунта, история операций
- Скользящая сводка диалога: каждые N сообщений пользователя (по умолчанию 3) отдельным дешёвым запросом пересобирается краткая сводка переписки, и дальше в контекст идёт именно она вместо длинной истории
- Экономия токенов: сводка вместо длинной истории, пропуск базы знаний и данных пользователя для коротких реплик, кеш ответов и эмбеддингов, обрезка слишком длинных сообщений, компактный системный промпт

### Как работает скользящая сводка (экономия токенов)

1. Каждый ответ считается «ходом» диалога; счётчик ходов пользователя растёт.
2. Как только с последней сводки набралось `SUMMARY_EVERY_N_TURNS` ходов (по умолчанию 3), запускается отдельный дешёвый запрос к ИИ, который сжимает новые сообщения (плюс прошлую сводку) в короткую рабочую заметку.
3. Дальше в системный промпт кладутся сводка и последние `CONTEXT_MESSAGES` сообщений — это резко снижает размер запроса при длинных диалогах, сохраняя контекст.

### Защита от выдумывания фактов

1. В системном промпте есть ПРАВИЛО ЧЕСТНОСТИ: слова-догадки («обычно», «наверное», «скорее всего») запрещены как замена точному факту.
2. Если модель всё же ответила догадкой на фактический вопрос (цена, срок, лимит, платёж) и база знаний ничего не дала — ответ автоматически заменяется на нейтральное «уточняю этот вопрос», а обращение эскалируется (`AISUP_HEDGE_ESCALATION`).
3. Маркер эскалации засчитывается только в самом конце ответа, поэтому пользователь не может вызвать эскалацию, попросив модель написать маркер в тексте.
4. Служебные уведомления уходят только в чаты из `AISUP_ADMIN_IDS`; автор обращения из списка получателей исключается, даже если он сам админ.

## Как работает RAG

1. Админ загружает JSON-экспорт переписки Telegram (формат Telegram Export).
2. Система извлекает сообщения, определяет реплики поддержки и пользователей, формирует пары «вопрос → ответ».
3. Каждая пара превращается в чанк, для него вычисляется эмбеддинг (OpenAI Embeddings) и сохраняется в векторную БД.
4. Дубликаты определяются по хешу содержимого — повторная загрузка того же файла или тех же пар не создаёт дублей.
5. При вопросе пользователя запрос сначала дополняется контекстом диалога (сводка + последние реплики), поэтому короткие уточнения вида «а для неё как?» тоже находят релевантные чанки.
6. Строится эмбеддинг запроса и ищутся ближайшие чанки. На PostgreSQL используется `pgvector` (индекс HNSW, поиск на стороне БД); при его отсутствии — векторизованный поиск через numpy с кешем матрицы. Переключается флагом `AISUP_PGVECTOR_ENABLED`.

## Запуск (standalone)

```bash
cd ai_support_bot
cp .env.example .env   # заполните токен бота, ключ OpenAI, доступ к БД/панели
docker compose up -d --build
```

Админка: `http://localhost:8090` (логин/пароль из `.env`).

## Запуск вместе с основным проектом

Сервис уже добавлен в корневой `docker-compose.yml` основного проекта как `ai_support_bot`.
Создайте `ai_support_bot/.env` (по образцу `.env.example`) и поднимите проект:

```bash
docker compose up -d --build
```

При работе на общей БД PostgreSQL основного проекта скрипт `init-db/create_ai_support_db.sh`
автоматически создаёт отдельную базу `ai_support` для бота при первой инициализации postgres.

## Режим секретаря Telegram

Бот поддерживает обычные личные сообщения и новые входящие сообщения в чатах подключённого
аккаунта Telegram. В режиме секретаря используются те же ИИ, база знаний, лимиты и передача
оператору. Данные аккаунта поддержки запрашиваются по Telegram ID собеседника, а не владельца
подключённого аккаунта. История собеседника общая с его прямым диалогом с ИИ-ботом.

1. В BotFather включите Secretary Mode для бота, чей токен указан в `AISUP_BOT_TOKEN`.
2. В настройках аккаунта Telegram откройте автоматизацию чатов, подключите этого бота,
   выберите чаты поддержки и разрешите отвечать на сообщения (`can_reply`). Для автоматической
   отметки обработанных сообщений прочитанными также разрешите `can_read_messages`.
3. Пересоберите сервис из корня проекта: `docker compose up -d --build ai_support_bot`.
4. С другого аккаунта отправьте новое текстовое сообщение или скриншот в разрешённый чат.

Дополнительные переменные окружения не нужны. Одного включения режима в BotFather
недостаточно: бот должен быть подключён к аккаунту и иметь право ответа. Перед обработкой
каждого сообщения права проверяются через Telegram API, в том числе после перезапуска.
Ответы и статус «печатает» отправляются от имени подключённого аккаунта; уведомления
операторам — отдельно от имени бота в `AISUP_ADMIN_IDS` и владельцу подключённого аккаунта.
Владельцу нужно открыть личный чат с ИИ-ботом и нажать «Запустить», чтобы получать уведомления.

После успешной отправки ответа без передачи оператору бот помечает входящее сообщение
прочитанным на подключённом аккаунте, если выдано право `can_read_messages`.
При передаче оператору последнее сообщение не помечается прочитанным, даже если предыдущие
сообщения диалога уже были прочитаны ботом. Ошибки генерации и доставки, лимиты и троттлинг
также не вызывают отметку прочтения. Если права на прочтение нет, бот продолжает отвечать
без изменения статуса прочтения. Уже прочитанный владельцем чат бот сделать непрочитанным не может.

### Пауза для работы оператора

- Любое новое сообщение, отправленное вручную от подключённого аккаунта (включая фото и голосовые),
  приостанавливает ИИ в этом чате на 30 минут с момента отправки. Следующее сообщение оператора
  продлевает срок. Сообщения самого ИИ не включают эту паузу.
- Уведомления о передаче оператору и достижении дневного лимита содержат кнопки «Взять в работу»
  и «Вернуть ИИ». Первая включает бессрочную ручную паузу, вторая снимает ручную и автоматическую
  паузы. Нажимать их могут только владелец подключения и администраторы из `AISUP_ADMIN_IDS`.
- Владелец также может открыть управление ботом из шапки клиентского чата: переход
  `/start bizChat<chat_id>` показывает те же кнопки для уже известного боту чата.
- Паузы сохраняются в таблице `business_chat_controls`, которая создаётся при запуске сервиса.
  Они действуют отдельно для каждой пары «подключённый аккаунт / клиентский чат».
  Во время паузы бот не отвечает и не отмечает сообщения прочитанными. После возврата ИИ
  обрабатываются новые сообщения; пропущенные автоматически не переигрываются.
- Перед отправкой ответа проверяется, не вмешался ли оператор во время генерации. Если пауза
  включалась, старый ответ подавляется, даже если ИИ успели включить обратно.

Встроенная пауза Telegram остаётся отдельным ручным переключателем в управлении ботом в шапке
чата. Её включает и снимает владелец средствами Telegram; Bot API не позволяет переключать её
нашими кнопками. «Вернуть ИИ» снимает только паузы приложения: если включена и пауза Telegram,
её тоже нужно снять в Telegram. Ошибка запрета отправки не вызывает повторную попытку ответа.

Сообщения ботов игнорируются. Правки и удаления сообщений
не вызывают повторного ответа ИИ. Старую переписку Telegram не загружает автоматически.
Telegram разрешает ответы в бизнес-чатах с входящими сообщениями за последние 24 часа.
Изменения подключения и прав записываются в журнал как `AI support business connection updated`.

Документация Telegram: https://core.telegram.org/bots/features#business-bots.

## Надёжность и безопасность

- **Админка без дефолтов.** У `AISUP_ADMIN_PASSWORD` / `AISUP_ADMIN_SECRET_KEY` больше нет значений по умолчанию. Если задать хотя бы одну переменную `AISUP_ADMIN_*`, сервис проверит их на старте и упадёт с понятной ошибкой при слабом или дефолтном значении (пароль от 10 символов, секрет от 32). Если админка не нужна — просто не задавайте эти переменные.
- **Объединение сообщений и очередь.** Быстрые сообщения одного чата собираются после паузы 1,5 с (ожидание пачки — до 4 с). Скриншоты, альбомы и пояснения идут в один запрос ИИ, до 10 сообщений за запрос. Все фото передаются Vision и сохраняются для оператора; дневной лимит считает объединённое обращение один раз. Сообщения, поступившие во время генерации, ждут следующего запроса. `AISUP_THROTTLE_SECONDS` (по умолчанию 4 с) задаёт интервал между запросами вместо отбрасывания сообщений. При настоящем флуде ограничивается очередь в 50 ожидающих сообщений на чат. Повторные обновления Telegram отсекаются до постановки в очередь. Очередь находится в памяти: при остановке сервиса ещё не обработанные сообщения не сохраняются.
- **Алертинг деградации.** Если данные пользователя не читаются из основной БД, бот больше не отвечает молча «без данных»: админам уходит уведомление (с троттлингом `AISUP_ALERT_THROTTLE_SECONDS`), а в промпт добавляется явный запрет утверждать что-либо о подписках и балансе.

## Переменные окружения

Все переменные имеют префикс `AISUP_`. См. `.env.example`.

Ключевые новые параметры:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AISUP_CONTEXT_MESSAGES` | `8` | Сколько последних сообщений истории идёт вместе со сводкой |
| `AISUP_RETRIEVAL_CONTEXT_MESSAGES` | `2` | Сколько последних реплик добавлять в поисковый запрос к базе знаний |
| `AISUP_HEDGE_ESCALATION` | `true` | Эскалировать вместо ответа догадкой |
| `AISUP_THROTTLE_SECONDS` | `4` | Минимальный интервал между запросами ИИ одного чата |
| `AISUP_PGVECTOR_ENABLED` | `true` | Использовать pgvector на PostgreSQL |
| `AISUP_ALERT_ADMINS_ON_FAILURE` | `true` | Уведомлять админов о сбоях чтения основной БД |
