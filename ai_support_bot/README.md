# AI Support Bot

Отдельный Telegram-бот ИИ-поддержки на базе RAG и GPT API. Работает самостоятельно (со своим токеном), поднимается вместе с основным проектом через общий `docker-compose`, но не зависит от кода основного бота.

## Возможности

- Честно представляется ИИ-ассистентом (никакой имитации живого оператора) и передаёт вопрос человеку, когда не знает точного ответа
- Отвечает пользователям в Telegram на основе базы знаний (прошлые переписки поддержки) через RAG
- Принимает и анализирует фото/скриншоты (GPT Vision)
- Подтягивает данные пользователя из БД основного проекта (баланс, подписки, платежи) и из Remnawave API
- Веб-админка с разделом ИИ-поддержки:
  - системный промпт, модель ИИ, температура, Top-K и другие параметры (меняются на лету, без перезапуска)
  - загрузка JSON-экспорта переписки как базы знаний (автоматическая разбивка на чанки, эмбеддинги, дедупликация — старые дубли не создаются повторно)
  - управление базами знаний (вкл/выкл/удаление)
  - история диалогов с ИИ-агентом (хранятся последние N сообщений, по умолчанию 100, чтобы не забивать память)
- Понимает намерение пользователя (техпроблема / оплата / инструкция / просто общение) и по-человечески отвечает на болталку («привет», «как дела», «спасибо»)
- Знает максимум о пользователе: подписки с остатком дней и трафиком, баланс, промогруппа, рефералы, ограничения аккаунта, история операций
- Скользящая сводка диалога: каждые N сообщений пользователя (по умолчанию 3) отдельным дешёвым запросом пересобирается краткая сводка переписки, и дальше в контекст идёт именно она вместо длинной истории
- Экономия токенов: сводка вместо длинной истории, пропуск базы знаний и данных пользователя для коротких реплик, кеш ответов и эмбеддингов, обрезка слишком длинных сообщений, компактный системный промпт

### Как работает скользящая сводка (экономия токенов)

1. Каждый ответ считается «ходом» диалога; счётчик ходов пользователя растёт.
2. Как только с последней сводки набралось `SUMMARY_EVERY_N_TURNS` ходов (по умолчанию 3), запускается отдельный дешёвый запрос к ИИ, который сжимает новые сообщения (плюс прошлую сводку) в короткую рабочую заметку.
3. Дальше в системный промпт кладётся именно эта сводка, а не вся история — это резко снижает размер запроса при длинных диалогах, сохраняя контекст.

### Защита от выдумывания фактов

1. В системном промпте есть ПРАВИЛО ЧЕСТНОСТИ: слова-догадки («обычно», «наверное», «скорее всего») запрещены как замена точному факту.
2. Если модель всё же ответила догадкой на фактический вопрос (цена, срок, лимит, платёж) и база знаний ничего не дала — ответ автоматически заменяется на нейтральное «уточняю у оператора», а обращение эскалируется (`AISUP_HEDGE_ESCALATION`).
3. Маркер эскалации засчитывается только в самом конце ответа, поэтому пользователь не может вызвать эскалацию, попросив модель написать маркер в тексте.
4. Служебные уведомления уходят только в чаты из `AISUP_ADMIN_IDS`; автор обращения из списка получателей исключается, даже если он сам админ.

## Как работает RAG

1. Админ загружает JSON-экспорт переписки Telegram (формат Telegram Export).
2. Система извлекает сообщения, определяет реплики поддержки и пользователей, формирует пары «вопрос → ответ».
3. Каждая пара превращается в чанк, для него вычисляется эмбеддинг (OpenAI Embeddings) и сохраняется в векторную БД.
4. Дубликаты определяются по хешу содержимого — повторная загрузка того же файла или тех же пар не создаёт дублей.
5. При вопросе пользователя запрос сначала дополняется контекстом диалога (сводка + последние реплики), поэтому короткие уточнения вида «а для неё как?» тоже находят релевантные чанки.
6. Строится эмбеддинг запроса и ищутся ближайшие чанки. На PostgreSQL используется `pgvector` (индекс HNSW, поиск на стороне БД); при его отсутствии — векторизованный поиск через numpy с кешем матрицы. Переключается флагом `AISUP_PGVECTOR_ENABLED`.

## Запуск (standalone)

```bash
cd ai_support_bot
cp .env.example .env   # заполните токен бота, ключ OpenAI, доступ к БД/панели
docker compose up -d --build
```

Админка: `http://localhost:8090` (логин/пароль из `.env`).

## Запуск вместе с основным проектом

Сервис уже добавлен в корневой `docker-compose.yml` основного проекта как `ai_support_bot`.
Создайте `ai_support_bot/.env` (по образцу `.env.example`) и поднимите проект:

```bash
docker compose up -d --build
```

При работе на общей БД PostgreSQL основного проекта скрипт `init-db/create_ai_support_db.sh`
автоматически создаёт отдельную базу `ai_support` для бота при первой инициализации postgres.

## Надёжность и безопасность

- **Админка без дефолтов.** У `AISUP_ADMIN_PASSWORD` / `AISUP_ADMIN_SECRET_KEY` больше нет значений по умолчанию. Если задать хотя бы одну переменную `AISUP_ADMIN_*`, сервис проверит их на старте и упадёт с понятной ошибкой при слабом или дефолтном значении (пароль от 10 символов, секрет от 32). Если админка не нужна — просто не задавайте эти переменные.
- **Троттлинг.** `AISUP_THROTTLE_SECONDS` (по умолчанию 4 с) не даёт зафлудить OpenAI: сообщения чаще лимита игнорируются, пользователь получает одно мягкое предупреждение. Плюс защита от повторной обработки одного и того же сообщения при retry Telegram.
- **Алертинг деградации.** Если данные пользователя не читаются из основной БД, бот больше не отвечает молча «без данных»: админам уходит уведомление (с троттлингом `AISUP_ALERT_THROTTLE_SECONDS`), а в промпт добавляется явный запрет утверждать что-либо о подписках и балансе.

## Тесты

```bash
python -m pytest ai_support_bot/tests -q
```

Покрыты: правила промпта, строгость маркера эскалации, контекстный поиск по базе знаний, детект догадок, разделение адресатов «ответ пользователю / уведомление админам», троттлинг, дедупликация апдейтов, ранжирование RAG и фолбэк с pgvector.

## Переменные окружения

Все переменные имеют префикс `AISUP_`. См. `.env.example`.

Ключевые новые параметры:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AISUP_CONTEXT_MESSAGES` | `12` | Сколько сообщений истории идёт в контекст (было 6 — мало для смены тем) |
| `AISUP_RETRIEVAL_CONTEXT_MESSAGES` | `2` | Сколько последних реплик добавлять в поисковый запрос к базе знаний |
| `AISUP_HEDGE_ESCALATION` | `true` | Эскалировать вместо ответа догадкой |
| `AISUP_THROTTLE_SECONDS` | `4` | Минимальный интервал между сообщениями пользователя |
| `AISUP_PGVECTOR_ENABLED` | `true` | Использовать pgvector на PostgreSQL |
| `AISUP_ALERT_ADMINS_ON_FAILURE` | `true` | Уведомлять админов о сбоях чтения основной БД |
