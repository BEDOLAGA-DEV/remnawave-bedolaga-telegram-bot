# hwid-blocker

Жёсткая блокировка устройств по HWID для Remnawave. Это небольшой Go-прокси без внешних зависимостей, который стоит между nginx/Caddy и страницей подписки Remnawave. Он перехватывает `GET`-запросы к подписке, читает аппаратный идентификатор клиента (заголовок `x-hwid`) вместе с short-UUID подписки и, если кортеж `(user_id, hwid, short_uuid)` есть в списке блокировок, отдаёт страницу «устройство заблокировано» вместо подписки. Все остальные запросы проксируются напрямую на страницу подписки.

**Бот** является единственным источником истины. Он владеет таблицей `device_blocks` и отправляет полное состояние в этот прокси. Прокси хранит небольшой снимок состояния на диске (чтобы перезапуск не сбрасывал блокировки) и при запуске заново запрашивает актуальное состояние у бота.

> Вся функция включается флагом окружения бота `DEVICE_BLOCK_ENABLED` (по умолчанию `false`). Если он выключен, можно запускать бота и кабинет **без** этого промежуточного слоя.

## Архитектура

```
Data plane:
  nginx (sub.domain) -> hwid-blocker :3020 -> subscription-page :3010

Control plane:
  bot :8080  --PUT /v1/state-->  hwid-blocker
  hwid-blocker --GET /device-blocks--> bot :8080   (загрузка при старте)
```

## Переменные окружения

| Переменная        | По умолчанию            | Обязательна | Описание |
|-------------------|-------------------------|-------------|----------|
| `LISTEN_ADDR`     | `127.0.0.1:3020`        | нет         | Основной listener (путь nginx). Фатальная ошибка, если не может занять порт. |
| `BOT_LISTEN_ADDR` | *(пусто)*               | нет         | Необязательный второй listener для сети моста с ботом. |
| `UPSTREAM_URL`    | `http://127.0.0.1:3010` | да          | Страница подписки Remnawave. |
| `STATE_FILE`      | `/data/state.json`      | нет         | Где сохраняется снимок состояния. |
| `ADMIN_TOKEN`     | *(пусто)*               | да*         | Токен для `PUT /v1/state`. Должен совпадать с `MIDDLEWARE_ADMIN_TOKEN` бота. |
| `BOT_API_URL`     | `http://127.0.0.1:8080` | нет         | Webapi бота (используется для загрузки состояния при старте). |
| `BOT_API_TOKEN`   | *(пусто)*               | нет*        | Токен, который webapi бота принимает для загрузки при старте. |
| `FAIL_OPEN`       | `true`                  | нет         | Если файл состояния не читается: стартовать с пустым состоянием (`true`) или отказаться запускаться (`false`). |

\* Нужны, чтобы бот мог отправлять/заливать состояние. Без них прокси всё равно работает (и проксирует трафик), но остаётся на последнем снимке.

## Установка — Docker

```bash
cd middleware/docker
cp .env.example .env        # затем отредактируйте: задайте два токена
docker compose up -d --build
```

- Сборка из корня `middleware/` (Go 1.24, статический бинарник, непривилегированный пользователь).
- Используется `network_mode: host`, чтобы достучаться до страницы подписки (`127.0.0.1:3010`) и webapi бота (`127.0.0.1:8080`) на хосте.
- Состояние хранится в `middleware/data/state.json`.

```bash
docker compose logs -f     # смотреть логи
docker compose restart     # перезапуск
docker compose down        # остановка
```

## Установка — без Docker

Требуется Go (>= 1.24) на хосте.

**Запуск в переднем плане (разработка / быстрая проверка):**

```bash
cd middleware/dockerless
cp .env.example .env        # затем отредактируйте
./run.sh
```

`run.sh` собирает статический бинарник в `middleware/bin/`, если его нет, и запускает его в переднем плане. Установите `REBUILD=1`, чтобы принудительно пересобрать.

**Установка как systemd-сервиса (продакшн):**

```bash
cd middleware/dockerless
cp .env.example .env        # затем отредактируйте (реальные токены)
sudo ./install-service.sh
sudo systemctl start hwid-blocker
```

`install-service.sh` собирает статический бинарник в `/opt/hwid-blocker`, копирует ваше окружение в `/etc/hwid-blocker/hwid-blocker.env` (0600), создаёт непривилегированного пользователя `hwid` и включает `hwid-blocker.service`.

## Интеграция с ботом

На стороне бота задайте (в `.env` бота):

```
DEVICE_BLOCK_ENABLED=true
MIDDLEWARE_URL=http://127.0.0.1:3020 (поддерживается https!)
MIDDLEWARE_ADMIN_TOKEN=<такой же, как ADMIN_TOKEN этого прокси>
MIDDLEWARE_PUSH_INTERVAL_MIN=30
```

- `MIDDLEWARE_ADMIN_TOKEN` ДОЛЖЕН совпадать с `ADMIN_TOKEN` этого прокси.
- `MIDDLEWARE_URL` должен указывать на listener, к которому привязан этот прокси. Если бот работает в контейнере в bridge-сети, используйте шлюз моста (например, `http://172.22.0.1:3020`) и задайте здесь `BOT_LISTEN_ADDR` соответствующим образом.

Отправка состояния выполняется по принципу «по возможности»: отсутствие промежуточного слоя никогда не ломает процесс бана/разбана в боте, а периодическая повторная синхронизация исправляет любое расхождение.

## nginx

Направьте серверный блок подписки на прокси и задайте заголовки, которые требует страница подписки:

```nginx
location / {
    proxy_pass http://127.0.0.1:3020;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## HTTP API

| Метод  | Путь           | Авторизация     | Назначение |
|--------|----------------|-----------------|------------|
| `GET`  | `/v1/health`   | —               | `{ok, version, count, uptime_s}` |
| `PUT`  | `/v1/state`    | `X-Admin-Token` | Отправка полного состояния `{version, devices[], updated_at}` |
| `GET`  | `/{shortUUID}` или `/path/{shortUUID}` | —               | Запрос подписки; заблокированным устройствам показывается страница блокировки, остальные проксируются |

Устройство считается заблокированным, когда его заголовок `x-hwid` и short-UUID из пути совпадают с записью `(user_id, hwid, short_uuid)` в текущем состоянии.

## Ручная сборка бинарника

```bash
cd middleware
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o bin/hwid-blocker .
```
