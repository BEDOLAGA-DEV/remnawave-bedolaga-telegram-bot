# Счётчик устройств по локациям

Источник данных для блока «Локации» на панели статистики кабинета («Админка → Панель статистики»):
сколько людей прямо сейчас сидит на каждой локации подписки.

Панель Remnawave считает онлайн по нодам, а не по локациям: если на одной ноде несколько хостов
(разные inbound'ы), панель не скажет, сколько людей на каждом. Эти данные есть только в access-логе
xray на ноде — в каждой строке видны inbound, outbound, IP клиента и пользователь. Счётчик читает
этот лог и раз в минуту отправляет в кабинет список устройств, которые подключались за последние
5 минут. Кабинет сводит отчёты всех нод: устройство (пара «пользователь + IP») считается только на
той локации, где было его последнее подключение, даже если до этого оно было на другой ноде.

## Приватность

В отчёте нет ни ID пользователей, ни IP-адресов. Пользователь и устройство передаются как
HMAC-SHA256 от общего токена (`u` = HMAC(токен, пользователь), `d` = HMAC(токен, пользователь|IP),
усечённые до 16 hex-символов). Токен одинаковый на всех нодах — иначе одно и то же устройство на
разных нодах не сведётся. Кабинет хранит только последний отчёт каждой ноды в Redis, 3 минуты.

Пример отчёта (`POST ${CABINET_URL}/api/cabinet/admin/stats/locations/report`, заголовок
`X-Location-Counter-Token`):

```json
{
  "node": "NODE-1",
  "generated_at": "2026-10-19T07:40:00Z",
  "window_seconds": 300,
  "devices": [
    {"u": "9f2c1a…", "d": "51be07…", "t": "2026-10-19T07:39:12Z", "inbound": "vless-auto", "exit": "DE1"}
  ]
}
```

## Требования

- На ноде — контейнер `remnanode`, Python 3.10+ (только стандартная библиотека) и docker.
- Access-лог xray не выключен в config-профиле (нет `"access": "none"` в секции `log`): remnanode
  пишет его в `/var/log/xray/current` внутри контейнера.
- Часы ноды синхронизированы (NTP): время в логе — UTC, расхождение больше 5 минут счётчик пишет в
  журнал предупреждением.
- Нода видит адрес кабинета по HTTPS.

## Настройка бота

В `.env` бота (см. раздел «ЛОКАЦИИ» в `.env.example`):

```bash
LOCATION_COUNTER_TOKEN=<openssl rand -hex 32>
```

Пустой токен — фича выключена: приём отчётов отвечает 404, блока «Локации» в кабинете нет.
Остальные настройки необязательны:

| Настройка | Зачем |
|---|---|
| `LOCATION_HOST_NODE_OVERRIDES` | Один inbound активен на нескольких нодах, а адрес хоста не совпадает с адресом ни одной из них — укажите, к какой ноде относится хост: `ru.example.com=RU-2,адрес2=ИМЯ2` |
| `LOCATION_EXIT_BREAKDOWN_INBOUNDS` | Теги inbound'ов, у которых на карточке показывается разбивка по выходам (см. ниже) |
| `LOCATION_SKIP_HOST_MARKERS` | Подстроки названий хостов, которые не являются локациями (например, разделители в подписке) |

## Установка на ноду

```bash
NODE_HOST=root@node1.example.com   # SSH-адрес ноды

# 1. Скрипт и unit
ssh $NODE_HOST 'mkdir -p /opt/location-counter'
scp scripts/location_counter/location_counter.py $NODE_HOST:/opt/location-counter/
scp scripts/location_counter/location-counter.service $NODE_HOST:/etc/systemd/system/

# 2. Окружение: файл сразу создаётся с правами 600 (токен не лежит открытым), затем правим
#    NODE_NAME (как в панели), CABINET_URL и токен
ssh $NODE_HOST 'install -m 600 /dev/null /etc/location-counter.env'
scp scripts/location_counter/location-counter.env.example $NODE_HOST:/etc/location-counter.env
ssh -t $NODE_HOST 'nano /etc/location-counter.env'

# 3. Запуск
ssh $NODE_HOST 'systemctl daemon-reload && systemctl enable --now location-counter'

# 4. Логи
ssh $NODE_HOST 'journalctl -u location-counter -f'

# 5. Проверка после запуска и после каждого рестарта: в контейнере ровно один процесс tail
#    (ps в контейнере нет, поэтому через /proc; "^tail" совпадает только с самим tail, а не с sh -c,
#    который его запустил). Должно напечатать 1; 2 и больше — остался хвост от прошлого запуска
ssh $NODE_HOST "docker exec remnanode sh -c 'grep -la \"^tail\" /proc/[0-9]*/cmdline 2>/dev/null | wc -l'"
```

Счётчик ставится на ноды, к которым подключаются пользователи. На выходы за мостом ставить его не
нужно: там виден только служебный пользователь моста.

Ошибка отправки отчёта пишется в журнал одной строкой, сервис ждёт следующей минуты. Если
`docker exec` завершился (например, перезапустился контейнер `remnanode`), сервис выходит с кодом 1
и systemd поднимает его через 10 секунд. Нагрузка небольшая: сервис ограничен 25 % CPU и 150 МБ
памяти, разбор лога в десятки тысяч строк занимает доли секунды.

## Как читать блок «Локации»

- Карточка — видимый в подписке хост панели (не выключенный и не скрытый), в порядке подписки. Хост
  привязывается к ноде по inbound'у config-профиля; если один и тот же inbound на одной ноде у
  нескольких хостов — карточка одна, с названием первого.
- Число — уникальные пользователи, у которых хотя бы одно устройство сейчас на этой локации. Человек
  с устройствами на разных локациях считается в каждой, поэтому сумма может быть больше онлайна.
- Нода без свежего отчёта (счётчик не стоит или молчит): если на ней одна локация — число берётся
  из панели с пометкой «по данным панели», если несколько — «—».

### Разбивка по выходам

Если inbound уводит трафик через балансир на несколько выходов (мосты на другие ноды), карточка
может показать, сколько людей ушло через каждый выход. Для этого:

1. На ноде задайте `EXIT_OUTBOUND_PREFIX` — общий префикс тегов outbound'ов-выходов. При
   `EXIT_OUTBOUND_PREFIX=BRIDGE_` outbound `BRIDGE_DE1` попадёт в разбивку как `DE1`, а `direct` и
   `block` — нет.
2. В `.env` бота перечислите теги таких inbound'ов в `LOCATION_EXIT_BREAKDOWN_INBOUNDS`.

Для устройства берётся outbound его последнего соединения в выход на этом inbound'е за окно;
устройство без такого соединения считается в общем числе, но не в разбивке.

## Откат

```bash
ssh $NODE_HOST 'systemctl disable --now location-counter'
```

Блок в кабинете вернётся к числам панели там, где на ноде одна локация. Полностью выключить
фичу (и скрыть блок) — оставить `LOCATION_COUNTER_TOKEN` пустым.
